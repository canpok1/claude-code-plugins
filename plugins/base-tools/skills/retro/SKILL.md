name: retro
description: 作業メモとこれまでの文脈をもとに作業全体の振り返りを行う時に使うスキル。振り返り結果をメモに追記し、完了後にアーカイブする。
allowed-tools: Read, Edit
---

## 手順

- [ ] ステップ1: 作業メモを取得・参照する
- [ ] ステップ2: これまでの文脈を整理する
- [ ] ステップ3: 振り返り観点で整理する
- [ ] ステップ4: 振り返り結果を作業メモに追記する
- [ ] ステップ5: 作業完了状態を確認する
- [ ] ステップ6: メモをアーカイブ移動する

## 注意点

- 全体
    - 各ステップで該当する目的のスキルが利用可能であれば積極的に活用すること。
    - 振り返りは事実ベースで記述すること。責任論や個人への批判にしないこと。
    - 作業メモが存在しない場合は、会話の文脈だけから振り返りを行うこと。
- ステップ1
    - 現在のブランチに対応する作業メモを取得・参照すること。
    - メモが存在しない場合はステップ2へ進むこと（文脈のみで振り返る）。
- ステップ2
    - 作業メモと会話の文脈から、以下の観点で情報を整理すること:
        - 実装内容: 何を実装・変更したか
        - 遭遇した問題: どんな問題やエラーに遭遇したか
        - 工夫した点: どのような工夫や判断を行ったか
        - 時間をかけた点: どこに時間がかかったか
- ステップ3
    - ステップ2の整理結果をもとに、以下の振り返り観点でまとめること:
        - うまくいったこと（Keep）
        - 改善すべきこと（Problem）
        - 次回以降に活かすこと（Try）
- ステップ4
    - 作業メモファイルが存在する場合、振り返り結果をメモの末尾に追記すること。
    - 以下のフォーマットで追記すること:
      ```markdown
      ## 振り返り

      ### うまくいったこと（Keep）
      - {内容}

      ### 改善すべきこと（Problem）
      - {内容}

      ### 次回以降に活かすこと（Try）
      - {内容}
      ```
    - 作業メモが存在しない場合は、`work-memo` スキルの仕組み（`get-memo-path.sh`）を使ってメモファイルを新規作成し、振り返り結果を書き込むこと。
    - 新規作成時は、目的や作業内容を会話の文脈から簡潔にまとめた上で、振り返り結果を記載すること。
- ステップ5
    - ステップ4で追記した作業メモの内容を確認し、以下の観点で作業完了状態を判定すること:
        - **チェックボックスの消化率**: 「作業内容」セクションのチェックボックス（`- [x]` と `- [ ]`）を集計し、全体の完了率を算出する
        - **振り返りセクションの有無**: 「## 振り返り」セクションが存在し、内容が記載されているか確認する
    - 判定基準:
        - チェックボックスが全て完了（消化率100%）かつ振り返りセクションが存在する → **完了**としてステップ6へ進む
        - 上記を満たさない → **未完了**と判定し、ユーザーに以下を報告して続行するか確認する:
            - チェックボックスの消化率（例: 2/5 = 40%）
            - 振り返りセクションの有無
            - 未完了のままdone/に移動してよいか、または移動せずに終了するか
    - 作業メモにチェックボックスが存在しない場合（新規作成メモや、チェックリストを含まないメモ）は、振り返りセクションの有無のみで判定すること。
- ステップ6
    - メモをアーカイブ移動すること。
    - 移動先のパスを確認し、アーカイブが完了したことを報告すること。
