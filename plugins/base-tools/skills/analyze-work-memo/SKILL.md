## 手順

- [ ] ステップ1: アーカイブ済みメモを収集する
- [ ] ステップ2: メモの内容を読み込み・分析する
- [ ] ステップ3: 改善点を抽出・整理する
- [ ] ステップ4: GitHub Issueを作成する
- [ ] ステップ5: 分析済みメモをアーカイブ移動する
- [ ] ステップ6: 結果を報告する

## 注意点

- 全体
    - 分析は事実ベースで行うこと。推測や主観的な評価は根拠となるメモの記述を添えること。
    - 改善Issueは具体的かつ実行可能な内容にすること。抽象的な提案は避ける。
    - 既存のopen Issueと重複するIssueを作成しないこと。ステップ4の前に `gh issue list` で確認する。
- ステップ1
    - アーカイブ済みの作業メモを収集すること。
    - アーカイブ済みメモが存在しない場合はその旨を報告して終了すること。
- ステップ2
    - 全てのアーカイブ済みメモを読み込むこと。
    - 各メモから以下の情報を抽出すること:
        - 作業の種類（機能追加、バグ修正、リファクタリングなど）
        - 遭遇した問題・つまずき
        - 振り返りのKeep/Problem/Try（存在する場合）
        - 作業の流れで非効率だった点
- ステップ3
    - 複数のメモを横断して、以下の観点で改善点を抽出すること:
        - 繰り返し発生している問題パターン
        - 複数のメモで共通して挙がっている改善提案（Try）
        - ワークフローやツールの非効率性
        - スキルやスクリプトの改善機会
    - 抽出した改善点をIssue単位にグルーピングすること。1つのIssueには1つの改善テーマを割り当てる。
    - 改善点が見つからない場合はその旨を報告して終了すること。
- ステップ4
    - 既存のopen Issueを `gh issue list` で取得し、重複がないか確認すること。
    - 重複しない改善点についてのみ `gh issue create` でIssueを作成すること。
    - Issueには以下を含めること:
        - タイトル: 改善内容を簡潔に示す
        - 本文:
            - 背景（どのメモのどの記述から抽出したか）
            - 改善提案の具体的な内容
            - 期待される効果
            - フッター（`🤖 Generated with [Claude Code](https://claude.ai/code)`）
        - ラベル: `enhancement`（存在する場合）
- ステップ5
    - 分析対象としたメモファイルを分析済みディレクトリへ移動すること。
    - これにより、次回実行時に同じメモが再分析されることを防ぐ。
- ステップ6
    - 作成したIssueの一覧（番号・タイトル・URL）を報告すること。
    - 改善点が見つからなかった場合や全て既存Issueと重複していた場合は、その旨を報告すること。
