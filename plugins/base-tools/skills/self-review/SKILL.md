---
name: self-review
description: 自分が書いたコードの変更内容をレビューし、指摘点を洗い出す時に使うスキル。
allowed-tools: Bash(git diff *), Bash(git log *), Read, Grep, Glob
---

## 手順

- [ ] ステップ1：変更差分を確認する
- [ ] ステップ2：レビュー観点で見直し、指摘点を列挙する
- [ ] ステップ3：指摘点を修正し、修正コミットを追加する

## 注意点

- 全体
    - 節目ごとに作業メモを残すこと。レビュー結果や修正内容を記録し、後続の作業で参照できるようにする。
    - PR作成・git push は行わないこと。責務はレビューと修正コミットまでに限定すること。
- ステップ1
    - `git diff` でステージ済み・未ステージの差分を確認すること。
    - `git log` で今回の作業に関連するコミット履歴を確認すること。
    - 変更対象のファイルを `Read` で読み、変更の文脈を把握すること。
- ステップ2
    - 以下の観点でレビューすること:
        - 可読性: 変数名・関数名は意図が伝わるか
        - 命名: プロジェクトの命名規則に沿っているか
        - 重複: 同じロジックが繰り返されていないか
        - 責務: 各関数・モジュールの責務は明確か
        - テストカバレッジ: 変更箇所に対するテストは十分か
        - セキュリティ: インジェクションや機密情報の露出がないか
        - エッジケース: 境界値やエラーケースの考慮漏れがないか
        - ドキュメント同期: スキル（`plugins/*/skills/*/SKILL.md`）を新規追加/削除したか、既存スキルの `description` を変更した場合、READMEのスキル一覧に同じ内容が反映されているか
    - 指摘がない場合はその旨を記録して完了とすること。
- ステップ3
    - 指摘点ごとに修正を行い、論理的にまとまった単位でコミットすること。
    - 修正後、再度差分を確認し、新たな問題が生じていないか確認すること。
