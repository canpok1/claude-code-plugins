argument-hint: "[issue-number]"
disable-model-invocation: true
---

## 手順

- [ ] ステップ1: GitHub Issueの内容を確認する
- [ ] ステップ2: Issueの要件に沿って対応を行う
- [ ] ステップ3: （実装した場合）/simplify を実行し、コードの品質を確認・改善する
- [ ] ステップ4: （実装した場合）自分が書いたコードをレビューし、指摘があれば修正する
- [ ] ステップ5: （実装した場合）プルリクエストを作成する
- [ ] ステップ6: （実装した場合）作成したプルリクエストのCI確認・レビュー対応・マージを行う
- [ ] ステップ7: 作業メモとこれまでの文脈をもとに振り返りを行う

## 注意点

- 共通
    - 各ステップで該当する目的のスキルが利用可能であれば積極的に活用すること。
    - 節目ごとに作業メモを残し、後続の作業で参照できるようにすること。
- ステップ1
    - 引数 `$ARGUMENTS` が指定されている場合はそのIssue番号のIssueを対象にすること。
    - Issueを特定できない場合やclosedの場合はユーザーに報告し、続行するか判断を仰ぐこと。
    - Issueの内容（タイトル、本文、ラベル、コメント等）から実装要件を整理すること。
    - 要件が不明確な場合はユーザーに確認すること。
- ステップ2
    - コードを変更した場合は論理的な変更ごとにコミットすること。
    - スキル（`plugins/*/skills/*/SKILL.md`）を新規追加/削除した場合、または既存スキルの `description` を変更した場合は、READMEのスキル一覧にも同じ内容を同一PR内で反映すること。
