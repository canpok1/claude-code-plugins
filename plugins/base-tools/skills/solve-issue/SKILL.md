argument-hint: "[issue-number]"
disable-model-invocation: true
allowed-tools: Skill(read-issue), Skill(tdd)
---

## 手順

- [ ] ステップ1：Issueの内容を把握する。
- [ ] ステップ2：Issueの対応を行う。
- [ ] ステップ3：（実装した場合）実装内容をレビューを行い、レビュー指摘を修正する。
- [ ] ステップ4：（実装した場合）プルリクエストを作成する。
- [ ] ステップ5：（実装した場合）プルリクエストのCI確認・レビュー対応・マージを行う。
- [ ] ステップ6：振り返りを行う。

## 注意点

- ステップ1
    - 引数 `$ARGUMENTS` が指定されている場合はそのIssue番号のIssueを対象にすること。
    - Issueを特定できない場合やclosedの場合はユーザーに報告し、続行するか判断を仰ぐこと。
    - Issueの内容（タイトル、本文、ラベル、コメント等）から実装要件を整理すること。
    - 要件が不明確な場合はユーザーに確認すること。
- ステップ2
    - 実装した場合は論理的な変更ごとにコミットすること。
