---
name: tdd
description: コードを実装する時に使うスキル。テスト駆動開発(TDD)で Red→Green→Refactor のサイクルをベビーステップで回す。
allowed-tools: Bash, Read, Grep, Glob, Write, Edit
argument-hint: "[task-description]"
---

## 手順
- [ ] ステップ1：テストリストをTODOコメントとして作成する
- [ ] ステップ2：テストリストが尽きるまで、以下のRed→Green→Refactorサイクルを1ケースずつ繰り返す
    - Red：失敗するテストを書く
    - Green：テストを通す最小限の実装を書く
    - Refactor：テストが通る状態を保ったままコードを整える

## 注意点
- 全体
    - PR作成・git push を行わないこと。責務はテストとプロダクションコードの実装・コミットまでに限定すること。
    - 節目ごとに作業メモを残すこと。テストリスト作成後、各サイクル完了時など、作業の区切りで記録する。
- ステップ1
    - 実装前に、必要なテストケースをTODOコメントとして列挙すること。**この段階ではコードを書かないこと。**
    - シンプルなケースから複雑なケースの順に並べること。
    - テストリストは途中で追加・変更してよい。
- ステップ2 - Red
    - テストを書く前にプロダクションコードを書かないこと。
    - 一度に複数のテストをRedにしないこと。
    - コンパイルエラーのままRedとみなすことも許容すること。
    - Red状態でコミットはしないこと。
- ステップ2 - Green
    - テストをGreenにすることだけを目的とし、最小限の実装に留めること。
    - Greenにするために定数を返す仮実装は許容すること。
- ステップ2 - Refactor
    - テストがGreenの状態を保ったままコードを整えること。
    - Refactor中はテストコードを変更しないこと。
